Tudo que dá pra fazer com um workspace agnóstico

Não migre o seu "cérebro" de um modelo pro outro. Separe o cérebro do modelo. Esta página é o mapa de tudo que o INEMA já construiu sobre o tema: kit, curso, diagnóstico, skills, executores e o evento.

Evento ao vivo em eventos.inema.pro: migrar do Claude Code pro Codex, ou ficar independente de modelo.

A ideia central é simples: só CLAUDE.md e AGENTS.md são presos ao provedor. Todo o resto do que você acumulou (contexto, regras, decisões, tarefas, skills, handoffs, memória) é Markdown portátil. Se esse material fica numa camada portátil dentro de cada projeto, Claude Code, Codex, Gemini ou um modelo local em container viram só executores, e trocar de modelo é trocar uma borda, não o centro.

Abaixo, o que existe hoje para colocar isso em prática, em ordem de uso: entender, diagnosticar, migrar, provar e manter.

3. O ciclo diário: handoff e prime

Duas skills canônicas, instaladas nos quatro executores a partir de uma única fonte.

📤
Skill · session-handoff

Fechar a sessão

Decisões, pendências, próximos passos, arquivos tocados e checks rodados viram handoffs/latest.md. É o resumo estruturado que viaja pra qualquer provedor.

📥
Skill · prime

Abrir a sessão

Lê AGENTS.md, context/, tasks/current.md e handoffs/latest.md antes de agir e devolve um briefing com fontes. Claude escreve, Codex retoma, e vice-versa.

🔁
Fluxo

Sessão → handoff → Markdown → prime → sessão

As sessões JSONL de cada runtime viram histórico, não fonte. O que sobrevive à troca de modelo é o Markdown do projeto.
